**A・B：検証を「通常更新を支えるもの」にする**

根拠：[固定件数の検証](D:/Projects/yuno-music-works/scripts/validate.mjs:53)、[更新情報を 1 件に限定](D:/Projects/yuno-music-works/scripts/validate.mjs:164)、[内部リンクの抽出](D:/Projects/yuno-music-works/scripts/validate.mjs:185)。

現行の検証は総作品数・分類別件数・更新情報件数を現在のカタログに固定している。README は JSON の直接編集を案内しているが、データの正常な追加だけではテストが通らない。一方、項目の存在確認だけでは空文字や真偽値の型違いを検出できない。日付は `Date.parse` による補正を許し、実在しない日付も通る。

内部リンク抽出の正規表現は `?` や `#` を含む URL 全体を抽出できない。結果として、全通常ページの `styles.css?v=...` や、プロフィールから作品へのクエリー・ハッシュ付きリンクが検証対象から漏れる。`localTarget()` にクエリーを除く処理はあるが、その前に抽出から漏れている。

| メモリ内だけで加えた変更 | 現行検証の結果 | 望ましい結果 |
| --- | --- | --- |
| 正常な更新情報を 1 件追加 | 失敗：`expected one update` | 成功 |
| 既存の単独オリジナル作品の日本語・英語タイトルを空文字に変更 | 成功 | 対象 ID・項目名を付けて失敗 |
| `published` を文字列 `"false"` に変更 | 成功 | boolean 以外として失敗 |
| 公開日を `2026-02-30` に変更 | 成功 | 実在しない日付として失敗 |
| HTML 読み取り結果の CSS 参照を `DOES-NOT-EXIST.css?v=...` に変更 | 成功 | 参照先不在として失敗 |

対応：本番 JSON は型・必須値・ID 一意性・日付・URL・親子関係などの不変条件で検証する。固定件数による回帰テストは小さなテスト用データへ移す。日付は年月日を分解し、生成後の値との一致まで検証する。URL は属性値全体を抽出してから分解し、ファイル・クエリーの作品 ID・ハッシュの対応を検査する。構文や関数名の文字列検査を中心にせず、検索・並べ替え・URL 正規化の結果をテストする。

完了条件：上の正常追加は通り、不正な 4 ケースは検出する。作品追加時に検証スクリプトの件数を書き換える必要がない。既存の CSP・許可 URL・親子整合性の検証も残る。

**C：読み込みと例外処理を直す**

根拠：[モジュール冒頭の localStorage](D:/Projects/yuno-music-works/assets/js/app.js:4)、[分類値の検査](D:/Projects/yuno-music-works/assets/js/app.js:369)、[共通 catch](D:/Projects/yuno-music-works/assets/js/app.js:603)、[初期状態で非表示の結果領域](D:/Projects/yuno-music-works/originals/index.html:44)。

`works.json` の取得に失敗すると、catch は `[data-work-list]` にメッセージを書き込む。しかし作品・編曲ページの親の結果領域は `hidden` のままであり、分類リンクも未生成となる。これはコードから追跡した問題で、実ブラウザーでの表示再現は未実施。

言語取得の `localStorage.getItem()` は try/catch の外にあり、例外時にスクリプト全体が初期化前に止まる。Node.js でストレージ例外を与えて停止を確認した。ブラウザー設定によってストレージアクセスが例外になることは [MDN の仕様説明](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)でも確認できる。

また、`ORIGINAL_GROUPS[selectedGroup]` の真偽値で分類を検査するため、`group=__proto__` や `group=toString` が通り、後続の `.includes()` が TypeError になる。該当関数を Node.js で実行して確認した。

対応：各画面に表示可能な loading／empty／error 状態と再試行を用意する。ストレージは安全な読み書き関数を通し、保存不能でも言語変更と表示が続くようにする。分類辞書は `Object.hasOwn()` または `Map` で許可値を判定する。基本ナビゲーションと JavaScript 未実行時の案内は初期 HTML に置く。

完了条件：JSON の 404・不正 JSON・通信失敗で見える位置に案内が出る。保存拒否でもページが使える。不正な分類値で例外が起きず、通常の分類選択に戻れる。

**G・H：作品単位の共有と日英表示を整える**

根拠：[単独作品を開くボタン](D:/Projects/yuno-music-works/assets/js/app.js:343)、[複数曲に限定された詳細ページ](D:/Projects/yuno-music-works/assets/js/app.js:583)、[言語変更](D:/Projects/yuno-music-works/assets/js/app.js:163)。

現在、独立した詳細ページが利用できるのは複数曲作品のみ。通常の単独作品と編曲は一覧内のボタンで開く。作品ごとに共有用のタイトル・説明・画像を持つ構成になっておらず、HTML に canonical・OGP・hreflang・サイトマップも用意されていない。

作品 URL と初期 HTML にタイトル・編成・説明・視聴／楽譜リンクを持たせると、共有先や JavaScript を実行しない利用者にも内容を伝えやすくなる。検索エンジンが JavaScript を処理できる場合もあるため「現状では検索されない」とは断定しない。作品発見をボタンやフラグメントだけに依存しない方針は [Google の JavaScript SEO ガイド](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)に沿う。

推奨案：小さな Node.js の生成処理を追加し、共通テンプレート＋既存 JSON から作品 HTML とメタ情報を生成する。公開サイトは引き続き静的ファイルとする。生成工程の追加に合わせ、README と公開手順も更新する。

日英は現在同じ URL で localStorage と再読み込みに依存する。リンクを送った相手に英語表示を指定できず、フォーム入力中の切り替えでは入力を失う可能性がある。日英別 URL（例：既存日本語 URL と `/en/`）を設け、対応ページをリンクで切り替える案を推奨する。これは [Google の多言語サイト向け説明](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)にも沿う。

最初に URL 対応表を決め、既存の作品 ID・slug・クエリー・ハッシュを保存する。言語ボタンの切り替え先は同じ作品・同じ条件とし、フォーム入力がある場合の保持方法を定める。英語ページでも日本語の作者名や「様」が残る項目、更新情報の「公開」と “alpha version” の意味の差も整理する。人名表記は推測で置き換えず、確認した表記をデータに持つ。

完了条件：単独作品・編曲も直接共有できる。初期 HTML に作品固有の内容がある。日英 URL と canonical・hreflang が整合する。既存リンクの回帰テストが通る。公開後に実際の共有プレビューと検索登録を確認する。

**改善計画への反映**

1. **I／P2：ヘッダーの修正を工程2の必須項目にする。** 761px ではデスクトップナビゲーションに切り替わるが、ロゴ・ナビゲーション・言語選択が1行に収まらない。日本語761pxでは言語選択の左端が約744.6px、右端が約842.4pxとなり、表示領域746pxを超える。820pxでも言語選択が一部画面外となる。ブレークポイントの見直し、折り返し、間隔・文字サイズの調整などで解消し、日英の760／761／820pxを再検証する。
2. **I／P2：Escape の条件分岐を修正する。** メニューが閉じた状態で本文の「オリジナル作品 →」リンクにフォーカスを置き Escape を押すと、`aria-expanded=false` のメニューボタンへ移る。開いているときだけ閉じる処理とフォーカス復帰を行う。
3. **H／P2：フォーム入力の保持を工程3の完了条件に明記する。** 言語変更前に入力した名前・メール・本文が、変更後はすべて空になる。入力の保持方法を実装し、実送信せずに日英往復の回帰確認を行う。
4. **C／P1：不正な分類値の拒否は予定どおり工程1で対応する。** `__proto__` の問題はコード上の推測からブラウザー再現済みに更新する。今回の不正値ではエラー文自体は見える。JSON 取得失敗時に親領域が hidden のままとなる別の問題は、今回の再現対象には含めていない。
5. **D／P2：動画枠の外側に視聴リンクを設ける案を維持する。** 「水鏡II」は YouTube のサムネイルと再生ボタンまで表示されたが、再生操作・音声出力は未確認。「Kids Return」は今回の埋め込み環境で再生不可の案内となった。YouTube 自身が iframe 内に「YouTube で見る」を表示した一方、サイト側には動画枠の外の視聴リンクがない。今回の結果だけで動画の削除や本番での恒久的な再生不可とは断定しない。
